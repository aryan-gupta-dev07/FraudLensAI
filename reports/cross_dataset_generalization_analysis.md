FraudLens AI

Cross-Dataset Generalization Analysis

1. Research Objective

The objective of this investigation was to understand the poor external validation performance of the existing FraudLens URL classification model.

During the initial independent evaluation, the model achieved approximately 28.56% accuracy on an external dataset containing 116,600 URL records.

Rather than immediately retraining or modifying the model, this investigation focused on identifying possible reasons for the generalization gap through dataset auditing, feature compatibility analysis, distribution comparison, prediction behaviour analysis, and threshold sensitivity experiments.

The original trained model was preserved throughout the investigation.

2. Experimental Setup

Training dataset:

- Records: 95,900
- Features: 10 numerical URL features
- Benign records: 48,009
- Phishing records: 47,891

Independent external dataset:

- Records: 116,600
- Original columns: 26
- Benign records: 100,000
- Phishing records: 16,600
- Missing values: 14 in the "tld" column
- Duplicate complete rows: 1,369

One external URL could not be processed by the local feature extractor. Therefore, the final experiments used 116,599 valid records, including 16,599 phishing records.

The existing FraudLens model was loaded without retraining or modification.

All URL processing was performed through local string parsing. No URLs were opened or visited.

3. Dataset Structural Audit

The two datasets differed in their structure, class distribution, and URL representation.

The training dataset contained a "domain" column, while the external dataset contained a "url" column.

Training examples frequently contained URL strings without an explicit HTTP or HTTPS scheme. The feature extractor automatically added HTTPS when no scheme was provided.

External examples generally contained explicit HTTP or HTTPS schemes.

This difference is particularly relevant to the "https_scheme" feature.

The training dataset had a constant HTTPS feature value of 1, whereas the external dataset contained both HTTP and HTTPS records.

Exact normalized URL overlap between the two datasets was zero. However, this alone does not establish complete statistical independence or eliminate possible shared-source biases.

The experiment did not retrain or modify the original model.

Key Observations

1. Increasing the threshold reduced false positives.
2. Increasing the threshold also increased false negatives.
3. Recall decreased from 92.70% at threshold 0.30 to 64.17% at threshold 0.90.
4. The highest F1-score among the tested thresholds was 0.2643 at threshold 0.30.
5. Even at threshold 0.90, the model produced 74,365 false positives.

Threshold adjustment alone did not resolve the external classification problem.

The threshold experiment is diagnostic and does not establish a production-optimal threshold.

Prediction Tie-Handling Note

The default "model.predict()" evaluation and the explicit "phishing_score >= 0.50" threshold evaluation produced slightly different confusion matrices.

This difference is consistent with possible differences in how tied class scores are handled by the estimator's prediction rule and the explicit threshold comparison.

The two evaluation procedures are therefore documented separately rather than combining their results.

8. Overall Findings

The investigation established several important observations:

- The training and external datasets have substantially different URL feature distributions.
- Their class proportions differ considerably.
- The training HTTPS feature is constant, whereas the external dataset contains both HTTP and HTTPS URLs.
- Several label-wise feature relationships differ between datasets.
- The existing model generates a large number of false-positive phishing predictions on the external dataset.
- The average phishing scores for actual benign and phishing records are very close.
- Increasing the classification threshold reduces false positives but increases false negatives.
- Threshold adjustment does not adequately resolve the external performance gap.

Collectively, these findings indicate poor cross-dataset generalization and weak class separation on the evaluated external dataset.

9. Limitations

The following limitations must be considered:

1. Only one independent external dataset was evaluated.
2. Zero exact normalized URL overlap does not prove complete independence between data sources.
3. Differences in dataset collection methods and label definitions may affect the evaluation.
4. Feature distribution comparisons do not independently establish causation.
5. The analysis did not establish whether dataset shift, source-specific patterns, or other factors were responsible for the observed performance gap.
6. Model scores were not calibrated against real-world phishing probabilities.
7. Threshold experiments were performed on the same external dataset used for evaluation. They should not be treated as independent validation of a selected threshold.
8. The external results should not be interpreted as representative of all real-world phishing URLs.

10. Final Conclusion

The Day 9 investigation identified substantial differences between the training and external datasets and documented the existing FraudLens model's poor performance on the independent evaluation dataset.

The prediction analysis revealed a high false-positive rate and weak separation between the phishing scores of actual benign and phishing records.

Threshold sensitivity experiments further demonstrated that adjusting the decision threshold changes the false-positive and false-negative trade-off but does not solve the underlying generalization problem.

The evidence supports the conclusion that the current model does not generalize reliably to the evaluated external dataset.

However, the exact causes of this performance gap remain unresolved and require further controlled experiments.

The original FraudLens model was preserved throughout the investigation. No retraining or model replacement was performed.

All experiments used local URL string processing. No external websites were opened or visited.
